# IoT 管理界面设计

日期：2026-11-10。任务：IOT-UI-01。角色：按用户指定 agency-agents-zh 技能采用界面设计（UI）专家工作方式。依据：用户提供的现有管理端截图、当前前端源码及后端管理接口。

物联网（IoT）管理放进现有 `web-unity` 工程，沿用同一登录、侧栏、主题和布局。IOT-UI-01 交付设计与[独立原型](prototypes/iot-management.html)；后续 IOT-M2-IMPL-01 已实现三个正式 Vue 页面，实际验证见[实施证据](../evidence/iot-m2-20261110/README.md)。静态原型不接后台，不能代替正式功能或真实联验。

## 1. 导航与页面落点

保留截图中的资源管理、场景管理，在场景管理下方新增同级分类“物联网管理”，包含三个业务页面：

```text
资源管理
  模型管理
  图片管理
  模板管理（按既有权限）
场景管理
  场景列表
物联网管理
  连接器管理
  设备绑定
  接收记录
```

管理入口属于现有管理外壳，不放入场景编辑器，也不新增登录系统。长菜单只滚动导航区域，底部主题/用户区固定；沿用当前侧栏收缩及品牌配置，原型中的文字品牌只用于展示层级。

用户明确物联网与资源、场景管理同级：正式页面顶层复用同一分类标题样式，不显示折叠箭头，三个授权入口直接展开。后端仍控制分类名称、菜单顺序及可见范围，只有更深目录继续使用可折叠菜单。

随后用户要求所有模块统一，NAV-01已将资源、场景与IoT全部接入同一授权树，旧静态入口过渡规则由[管理导航统一设计](02_管理导航统一设计.md)覆盖；实际检查与迁移边界见该任务证据。

### 1.1 菜单树由后端管理

用户同轮提出由后端管理导航节点树，纳入默认设计：后端负责目录层级、显示名、图标键、排序、启停、可见性和角色分配；前端负责已安装页面组件及安全路由映射。“资源管理”“场景管理”“物联网管理”对应目录，子页面对应菜单，按钮权限单独管理，不混入侧栏。

复用系统菜单管理 `/admin-api/system/menu`、角色菜单分配和 `/admin-api/system/auth/get-permission-info`，不新建IoT菜单表。标准登录保留menus，标准后台的内嵌/交接身份在业务挂载前补读。当前Header已统一渲染三个模块的授权树，资源/场景不再提供静态副本；缺失菜单进入管理访问提示页。

白名单组件标识固定为 `iotManage/connectors/index`、`iotManage/bindings/index`、`iotManage/messages/index`。后端 component/path 不用于执行脚本或加载远程组件；未知组件不挂载，部署时核查组件配置。新建菜单不等于无需前端发版便获得新业务页面。

登录/恢复时，从当前应用、平台、租户和用户上下文获得菜单，保留现有认证路径兼容性。标准权限接口已按角色取菜单、过滤停用项并按 sort 构树；应用及租户套餐边界须在实际管理权限链路再次核对。前端过滤未知路由和不可见节点，隐藏菜单与取消接口权限分别处理，按钮权限仍由服务端逐次校验。

菜单纳入当前可信身份，退出或切换身份清理；会话恢复重新读取。首期配置生效采用刷新权限或重新登录，接口逐次鉴权。标准认证权限读取失败沿用登录错误恢复；内嵌补读失败关闭 IoT 入口，刷新页面重新尝试，不回退全量。解析最多1000节点、12层，重复路由仅挂一次。

菜单配置复用已有管理入口及 `system:menu:*` 权限，不向普通 IoT 操作者开放配置。IoT 页面消费授权菜单且交叉校验查询权限；[增量菜单清单](../../../../Server/jtyf-cloud/wx-module-iot/db/iot-management-menus.json)用于目标环境按系统接口配置及角色分配，目前尚未执行线上配置。

正式路由及组件如下，均已注册；仍需实际部署及目标身份授权：

| 页面 | 拟议路由 | 拟议视图位置 | 首期任务 |
| --- | --- | --- | --- |
| 连接器管理 | `/iotManage/connectors` | `src/views/iotManage/connectors/index.vue` | 连接配置、启停、结构校验、受限测试及状态查看 |
| 设备绑定 | `/iotManage/bindings` | `src/views/iotManage/bindings/index.vue` | 外部设备与内部设备/场景对象的映射 |
| 接收记录 | `/iotManage/messages` | `src/views/iotManage/messages/index.vue` | 接收结果、失败摘要及有权限的重放 |

## 2. 视觉与布局

复用实际组件/样式入口：[管理布局](../../src/layout/index.vue)、[侧栏](../../src/layout/Header.vue)、[管理主题](../../src/views/manageShared/theme.scss)、[管理能力](../../src/auth/capabilities.ts)。原型使用相同主色 `#51a195`，浅灰底、白色内容板和细边框，正式实现改用已有主题变量及组件，不再复制一份主题系统。

- 桌面端：固定原管理侧栏；主区依次为页头、筛选区、表格区及分页。页头右侧仅一个主要动作，连接器页为“新增连接器”。
- 表格替代场景卡片：IoT 需要同时比较协议、启用状态、实际观测和配置版本，表格更便于扫描；不沿用模型/场景的封面卡片。
- 行高约 68 像素，主操作不少于 32 像素；名称/业务编号双行显示；编号使用等宽字体且可复制。
- 主色表示选中和操作；绿色/灰色表示启用，实际运行状态另设独立标签。所有状态同时有中文文字，不能只靠颜色辨识。
- 详情/编辑使用右侧抽屉，宽度约 520～580 像素，保留列表筛选位置。删除、停用、重放等影响动作单独确认；普通查看无需确认。
- 窄屏收缩为图标侧栏，表格允许横向滚动，抽屉在小屏占满宽度；正式实现沿用已有布局的断点，不重新设计移动端壳。
- 主题沿用全局亮暗切换。键盘可聚焦导航、表单和操作；抽屉带标题和关闭按钮，Esc 关闭，关闭后焦点返回触发按钮。

## 3. 连接器管理

筛选：名称/业务编号、协议、期望启用状态；查询与重置沿用现有按钮样式。结构上允许启用后未接管的合法情况，不把“启用”直接渲染为“在线”。当前接口不提供整体在线数，首期不展示虚构的全量在线率或实时设备总数。

| 列 | 展示规则 |
| --- | --- |
| 连接器 | 显示名称及 connectorId；数据库主键不替代业务编号 |
| 协议 | MQTT/HTTPS/MOCK，对应后端已登记驱动；不列未实现的工业协议 |
| 启用状态 | 期望启用/停用，与运行观测分开 |
| 运行观测 | 详情读取 runtime；列表未查询的行显示“未观测”，不得逐行轮询制造大量请求 |
| 配置版本 | 展示 version，注明是配置版本，不是运行版本 |
| 最近更新 | 使用服务端时间，不伪造最近消息时间 |
| 操作 | 查看、编辑、更多；更多中按权限显示启停、测试和删除 |

抽屉内容：基本配置、运行观测、关联设备、接收记录。运行观测显示 observedAt、persistedStatus、effectiveStatus 和 leaseActive；过期租约显示“租约已过期”，非 MQTT 显示“不适用”。数据库快照不是当前网络、Kafka 或设备业务健康证明。

新增/编辑表单：显示名称、业务编号、协议、连接地址、凭据引用、主题及映射配置。新建默认停用；凭据只填写已部署引用，禁止明文密码/密钥输入。MQTT 主题按当前确切主题及服务质量等级（QoS）1 规则校验，不默认支持通配或任意协议。

结构校验与连接测试分开：结构校验可以在保存前进行；连接测试仅针对已保存、当前租户的连接器，显示实际超时及脱敏结果，不修改正式运行状态。没有凭据或目标权限时显示明确原因，不假报成功。

保存成功后保留筛选并更新列表；旧 version 冲突时保留用户表单，提示“配置已被更新，请刷新后确认”，不自动覆盖他人变更。完整密钥后台及轮换属于后续阶段，不在首批表单里预留看似可用的密码管理按钮。

## 4. 设备绑定

筛选：连接器、外部设备编号、启用状态。列包含外部设备编号、内部设备编号、连接器、映射版本、状态和操作；场景/对象关联在详情中展开，避免主表过宽。

首批表单输入连接器业务编号，后端校验当前租户连接器存在；内部设备/场景/对象沿用现有绑定键，不据输入赋予资源访问权限。真实场景对象归属联验保留在验收清单。点位映射使用已有JSON结构，服务端最终校验；抽屉关闭和站内路由离开提醒未保存输入。

后端已补 `page`，数据库执行有界分页及连接器/外部设备/启用筛选；旧list保留兼容。绑定目前最后保存生效，尚无配置版本冲突控制，页面明确提醒避免多人同时编辑。

## 5. 接收记录

筛选：连接器、处理状态；需要事件编号/时间筛选时先补合同，不猜测现有参数。表格显示事件号、连接器、外部设备、接收/处理结果、时间和脱敏失败原因。

失败行突出文字原因和“查看详情”，人工重放只向有 `iot:message-inbox:replay` 权限且满足后端条件的用户显示。重放确认明确是重发同一事件，不改事件身份；成功提交重放不等于设备已执行命令。无 Kafka 等依赖时明确失败/限制，不能静默成功。

详情展示允许的诊断字段和时间线，不向页面输出凭据、签名、令牌及完整未经审查的遥测原文。原型不展示真实业务报文。

## 6. 统一状态与权限

| 页面状态 | 用户看到什么 | 恢复方式 |
| --- | --- | --- |
| 加载中 | 表格骨架/加载提示，保留筛选值 | 请求完成后更新，不重置筛选 |
| 空数据 | “暂无连接器/设备绑定/接收记录”，给出当前页适用动作 | 新增或调整筛选；空数据不是请求失败 |
| 加载失败 | 明确失败提示，不能保留假成功数量 | “重新加载”，保留输入和上下文 |
| 无权限 | 403 及说明；正式侧栏和路由同时限制 | 返回有权限页面，不要求用户尝试绕过 |
| 版本冲突 | 保留草稿和版本冲突提示 | 刷新服务器版本后由用户确认，不盲目自动重试 |
| 动作未验证/条件缺失 | 说明缺少凭据、Broker 或消息通道 | 禁用动作并给出原因，不阻断其他已可用管理功能 |

沿用 `iot:connector:*`、`iot:device-binding:*`、`iot:message-inbox:*` 服务端权限；前端能力来源接入现有认证映射，不能从“运营端”或“超级管理员”文字推断跨租户权限。只读用户不能因看到页面就获得写动作。正式实现须同时检查入口、路由、按钮、处理函数和后端接口。

## 7. 后端接口交接

后端源码已核实业务成功码为 200，分页为 data.list/data.total；与已有 Web 请求封套对齐后再实现页面。全部编号在前端保留字符串精度，后端旧 Long 字段如何序列化必须在合同阶段确认。

| 页面 | 复用接口 | 待补/限制 |
| --- | --- | --- |
| 连接器 | `/admin-api/iot/connector` 的 page/get/create/update/delete/enable/disable/runtime/validate-mqtt-config/test-mqtt | runtime 只按需查，列表不臆造实时状态；具体错误与版本规则待合同收口 |
| 设备绑定 | `/admin-api/iot/device-binding` 的 create/update/delete/get/list/page | 已补真实数据库分页与保存映射校验，绑定并发为最后保存生效 |
| 接收记录 | `/admin-api/iot/message-inbox/page` 与 POST replay(eventId) | 重放需要真实接收记录、Kafka 及权限，不能由原型数据推断可用 |
