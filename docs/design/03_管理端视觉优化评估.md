# 管理端视觉优化评估

日期：2026-11-10。任务：UI-REVIEW-01。按用户指定agency-agents-zh技能，以界面设计专家视角评估。结论：需要视觉精修，优先提升可读性和操作效率，保留青绿色品牌与NAV-02确认的一二级目录。本批为评估，没有修改运行样式。

## 1. 依据与边界

- 当前结构依据[原目录截图](../evidence/nav02-20261110/original-navigation.png)，不是新设计效果图。
- 场景筛选/空态参考NAV-01历史截图，仅用于布局观察；其中改名测试目录已被NAV-02覆盖，不再作为交付目录。
- 核对共享theme.scss、管理页标题/筛选/分页组件、侧栏、IoT表格及抽屉源码。现有公共组件和主题变量可以复用，不需要另建组件库。
- 当前只评估管理端，未检查完整编辑器、全部抽屉交互、实际暗色页面、200%缩放及窄屏溢出；不能称完整无障碍验收。

## 2. 优先级与建议

| 优先级 | 当前观察 | 优化方向与验收 |
| --- | --- | --- |
| 高：可读性 | 12px浅灰面包屑、13px次级说明，以及绿底白字在截图中偏淡；主正文#595959配白底本身对比充分，不能笼统调黑全页 | 区分主正文、次级说明、占位和禁用色；正文建议14px，说明13px，重要信息不靠浅灰弱化。常规文本以4.5:1为检查目标，重要状态同时保留文字 |
| 高：动作主次 | IoT行内详情/编辑/启停/删除同时排列，三个普通动作同为绿色文字，删除紧邻启停 | 每页保留一个主按钮；行内突出查看/编辑，低频启停及危险删除进入更多菜单，保留确认与权限检查。键盘仍可访问所有授权动作 |
| 中：筛选布局 | 共享字段固定242px，场景四个字段加按钮在1440截图中换为两排；动作和内容起点随字段数改变 | 用共享响应式网格，字段宽度允许约180～240px，按钮组统一对齐；1440可容纳时保持一排，1024有序换行而非挤压，1280/1440/1920分别留图 |
| 中：标题层级 | 当前16px常规绿色标题，紧跟12px浅灰重复路径，标题与正文区分较弱 | 候选标题18～20px、正文14px；面包屑作为次级信息，减少当前标题的重复。现有字号/400字重来自既有设计约定，实施前做同屏对比，不能静默改变全局字体 |
| 中：侧栏层级 | 三个业务分类已正确，但60%白色一级文字偏弱，活跃项主要靠浅色胶囊；280px侧栏在1024下留给内容的宽度有限 | 保持分类、顺序、图标和选中位置；强化分类可读性与当前入口边界。280px先作为基线，后续比较紧凑或折叠模式，不直接全局缩窄 |
| 中：页面一致性 | 场景使用资源卡片、IoT使用表格合理；但筛选按钮/标题/表格链接仍有页面级覆写，列表32px与通用36px控件并存 | 在同用途控件中统一高度、间距、圆角和主次颜色；表单可有独立尺寸。复用现有共享组件，仅收敛必要变量，避免追加更多!important |
| 后续：长表单/空态 | 绑定抽屉字段与JSON编辑较长，运行观测和配置说明密集；场景空态大但下一步引导较弱 | 抽屉按基本配置/映射/运行状态分段，保留底部保存；后续提供普通配置与高级JSON两种编辑方式。空态区分未创建与筛选无结果，并给出对应操作；不为填留白捏造统计 |

品牌水印在源码中有既有用户确认的尺寸与位置记录，当前不直接调整。若后续同屏对比确认它影响导航阅读，再评估局部明暗和装饰权重；本次不能根据个人偏好重做品牌区。

## 3. 静态配色计算

普通文本的最低对比参考[W3C对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。该说明给出常规文本4.5:1、大号文本3:1的判断，禁用/装饰等存在例外；不能把所有元素一概套用同一阈值。

| 配色位置 | 源码值与计算底色 | 约算对比度 |
| --- | --- | --- |
| 主正文 | #595959 / #ffffff | 7.00:1 |
| 次级正文 | rgba(89,89,89,0.68)混合白底 / 白底 | 3.28:1 |
| 面包屑 | #b8b9bb / #f6f8f9 | 1.84:1 |
| 主色上的白字 | #ffffff / #51a195 | 3.05:1 |
| 一级分类 | 60%白混合#51a195 / #51a195 | 2.03:1 |
| 深绿交互色候选 | #ffffff / #28786d | 5.25:1 |

计算记录见[配色证据](../evidence/ui-review-20261110/contrast.json)。以上按静态纯色合成计算，未计背景水印、渐变和实际计算样式；深绿只是交互色候选，不能直接当作已确认品牌替换方案。

## 4. 建议实施顺序

第一批先优化文字/交互对比、筛选布局和表格操作主次，覆盖资源、场景、IoT的公共底座；当前目录结构、后台授权、运行状态语义及编号精度继续沿用。

第二批再优化标题/抽屉分段、空态引导与窄屏密度。验证应使用亮暗主题、空/加载/失败/禁用/冲突状态，在1280/1440/1920宽度和200%缩放下核查；JSON编辑不得因美化或重序列化丢失十进制原文，不新增逐行运行轮询。

本批只完成评估与建议，未改src、未生成新效果稿、未重新构建业务、未部署。后续应先交付一页可比较的真实页面样式，再按确认的视觉方案应用共享组件。

## 5. 第一批实施（UI-01）

用户已要求推进。首批收敛主题内文本和交互色，共享筛选采用有最小宽度的响应式网格并稳定按钮区；IoT行内保留详情/编辑，启停与删除移入明确标识的更多菜单，原权限、确认和在途互斥逻辑继续使用。品牌图形、水印大小位置、280px侧栏及NAV-02目录保持。

列表继续区分期望启用与实际运行，更多菜单不增加运行轮询；明暗主题均验证菜单、传送浮层、抽屉与焦点。布局及颜色仅在管理主题作用域生效，不传播到编辑器/公开预览。具体检查及实际修改以UI-01台账和证据为准。

2026-11-11按用户“浅色主体，字体颜色太黑”反馈，浅色正文采用中灰绿`#606d68`、次级说明`#69756f`，青绿侧栏恢复白字。主按钮使用深绿填充承载白字，不改变品牌背景。当前主按钮实测对比约5.25:1、说明约4.80:1；侧栏品牌配色约3.05:1，仅记录，不宣称整页达到无障碍对比目标。

第一批本地实施及验证已收口，见[交付证据](../evidence/ui01-20261110/README.md)。浏览器23项、导航/IoT测试77项、类型/构建及二维适用回归通过；尚未部署，真实200%缩放、完整移动端及第二批抽屉/空态优化不在本次完成范围。
